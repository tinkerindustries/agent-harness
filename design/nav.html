What changes

  • One React component, mounted once by App.tsx around whichever screen the route picks, not re-declared inside each screen. Active state is route.kind compared against each link's own kind — "list" and "session" both count as the sessions section for this purpose, and only "session" renders the crumb.
  • Every screen keeps its page-specific right-hand content (the connection badge, the search input, the refresh button) — the nav only standardises the left two-thirds. Nothing about data fetching or writes changes; this is layout only.
  • The /perf harness route is a developer tool, not a product screen (web/CLAUDE.md), and does not get the nav.
