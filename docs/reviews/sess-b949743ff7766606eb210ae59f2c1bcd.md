## Mechanical failures

None. Every error, rejection and retry in this log traces to the model's own
call or to the model's own scratch mock server. Specifically:

**The two `Complete` rejections (sub-turns 277–278, $0.0035, 34s) are the
model's.** At 277 the result object omitted the schema's required `error`
field. At 278 the model added `error` and, rebuilding the whole call, dropped
the top-level `summary` argument it had got right at 277 — so
`execComplete`'s first guard fired (`internal/tools/complete.go:26`). It
succeeded at 279. Worth stating plainly because the shape of this is easy to
misread as a validator problem: it is not. Note also what did *not* happen —
the model nested the schema's fields inside `result` correctly on both
attempts, so `flatResultHint`, the fix that came out of
[the phase-5 review](sess-bb6c0ed564ddae573c3b1832cb3981f4.md), never had to
fire. That failure mode did not recur.

**The container's `grep` is busybox, not GNU.** `--include` was rejected at
sub-turns 23, 152 and 172 — one wasted sub-turn each, three times across the
run. This is the environment behaving as configured, not a fault, but see the
ranked fixes: the model never learned it within the session.

**No node_modules in the clone** (sub-turns 56–58): `vitest: not found`, then
`npm install`, recovered in two sub-turns. Expected — `web/node_modules` is not
in git.

## Where the model struggled

**One ambiguous clause in the brief cost 167 seconds and 22,500 reasoning
tokens.** Sub-turns 35 and 36 ($0.0077, 7% of the run's wall clock in two
sub-turns) are almost entirely one paragraph of item 1 being read over and over:

> Remove the derivation and its comment. Keep the fallback for a block that has
> no sub-turn, so an old log still renders.

The model enumerated two readings — delete `steerDeliveredSubTurn` outright, or
demote it to the fallback — argued itself into each at least twice, declared an
"executive decision", then reversed it, then reversed back. It settled on
removal, with a delivered block that has no `appliedSubTurn` rendering a plain
"delivered". That is almost certainly what was meant, and the model documented
the choice in the commit message. The cost is entirely attributable to the
brief: "the fallback" is a definite article pointing at a noun the brief never
introduced.

**Two long bug hunts, both correct, both slow.** Finding the footer grid bug
took 22 sub-turns (187–208, ~$0.024) and finding the banner remount took 26
(216–241, ~$0.028). Both were genuinely hard — the first because the symptom was
a computed `grid-template-columns` of `193.469px 758.531px` that matched no rule
in the stylesheet, the second because the state being reset was invisible from
the DOM. The model got both right by elimination: probe elements with and
without children, a CSSOM dump of every matching rule, disabling rules one at a
time, and finally a temporary `data-debug-banner` attribute it removed
afterwards. That is the right method. It is just not a fast one.

**Six sub-turns of the banner hunt were spent on a phantom** (226–230). The page
under test was `chrome-error://chromewebdata` — the mock server had been killed
by the previous command — so every `eval` returned `undefined` and the model
read that as "the component is not mounted". It caught this at 229 by checking
`location.href`, and its very next test (230) included an explicit URL assertion.

**Its own scratch mock produced four false alarms** before it was faithful
enough to test against: `/api/stream` answered as JSON (22 sub-turns, 132–156),
plan tool calls with no matching `tool_result` leaving five phantom pending
tools, a `TaskCreate` payload whose in-progress item made the phases read
3, 2, 3, and a reconnect that replayed the whole history because the mock
ignored `Last-Event-ID`. Each was diagnosed correctly and each fix made the mock
closer to the real harness — but roughly a third of the browser pass was spent
debugging the test rig rather than the product.

## What it missed

**The playwright-cli skill's own reference for the command it was fighting.**
Sub-turns 136–143 are eight sub-turns of `run-code` failing — first
`SyntaxError: Unexpected token ';'`, then `setTimeout is not defined` twice. The
skill it had already read lists
`references/running-code.md`, which states that the code "must be a single
function expression, it is wrapped in `(...)` and evaluated" — the trailing
semicolon at 136 is exactly that mistake. Reading the reference would have saved
the first failure; the `setTimeout` restriction is documented nowhere, so the
`page.waitForTimeout` discovery was earned.

**Its own no-op retry at 140–141.** After `setTimeout is not defined` at 139,
the model wrote the identical file content and re-ran the identical command,
receiving the identical error. This is the only repeat the metrics script
flagged, and it is a genuine one: nothing changed between the two attempts.

**`pkill -f` matching its own shell.** At 145 and again at 157 the mock-server
restart killed the shell running it (its command line contains the pattern),
returning exit -1 with no output. The model diagnosed it correctly at 159 and
moved to a pid file — but it had already lost two sub-turns and one confusing
"server down" reading to the same cause.

## Ranked fixes

**1. (Product bug, `web/src/hooks.ts`) Stop remounting the whole session screen
on every SSE reconnect.** This is the most valuable thing the run found, and it
only worked around it. `useSessionMeta(sessionId, snapshot.connection)` calls
`setSettled(false)` at the top of its fetch effect, so every connection change
sends `SessionScreen` back to its `!settled` shell and unmounts whichever screen
the fork was rendering. The browser's EventSource reconnects on its own a few
seconds after any drop, so this fires in normal operation. What it discards each
time: `SessionChatScreen`'s `sentAt` map (the local timestamps a pending steer's
count-up is measured from) and its `failed` ledger (failed sends with their Retry
buttons — nothing in the log will ever bring these back), both screens'
stop-confirm state, the follow-the-tail state, and the watch page's filter and
find-box query. The run's fix — hoisting one flag to `SessionScreen` — makes the
banner work and leaves everything else exposed. The narrow repair is to
re-fetch without clearing `settled` when only `refreshOn` changed; `settled`
exists to distinguish "row not here yet" from "row will never arrive", and a
refetch on an already-settled row answers neither question. Still live in `main`.

**2. (Prompt) Fix the ambiguous clause in the phase-4 brief, and the pattern
behind it.** "Remove the derivation and its comment. Keep the fallback for a
block that has no sub-turn" cost 167 seconds and 22,500 reasoning tokens because
"the fallback" refers to something the brief never named. Whoever writes the next
phase brief should say which artefact survives: "delete `steerDeliveredSubTurn`;
a delivered block with no `appliedSubTurn` renders `delivered` with no sub-turn
named" would have cost the model nothing. Cheapest fix in this list.

**3. (Tool description, `internal/tools`) Make `ReviewScreenshot`'s cost visible
where the model chooses to call it.** Seven calls cost $0.1228 — 32% of the
run's total spend — against $0.0010 for a typical sub-turn. One call (163)
produced the finding that led to a real fix. Two returned empty arrays. Four
returned false positives that cost further sub-turns to refute. The worst case is
sub-turns 182–183: the reviewer returned `[]` for $0.0277, the model immediately
re-asked the same screenshot for another $0.0208, got two false positives, and
spent two more sub-turns measuring geometry to disprove them. An empty result is
an answer; the tool's description should say so, and should say what a call
costs relative to a sub-turn, so re-asking looks as expensive as it is.

**4. (Prompt) Teach the container's shell surface once, at the top.** Three
sub-turns died on busybox `grep` rejecting `--include`, spread across 150
sub-turns, and two more on `curl: not found`. A line in the opening message —
busybox coreutils, no `curl` (use `node -e` or `wget`), prefer the `Grep` tool
over `grep -r` — would have returned all five, and would generalise to every run
in this image.

**5. (Skill) Point at `references/running-code.md` from the failure, not just the
index.** Eight sub-turns went into rediscovering the `run-code` calling
convention that the reference states in its second paragraph. The skill file is
generated and must not be hand-edited, so the fix belongs upstream in
`playwright-cli`: make the `SyntaxError` from a non-expression script name the
reference. Failing that, a repo-side note in `web/CLAUDE.md` for anyone driving
the browser.

**6. (Prompt) When driving a browser, assert the page loaded before reading from
it.** Six sub-turns of the banner hunt were spent interpreting `undefined` from a
`chrome-error://` page as evidence about a React component. The model itself
adopted the fix mid-run — every later `eval` returns `location.href` alongside
the thing it is checking. Worth stating as a rule wherever browser guidance
lives.
